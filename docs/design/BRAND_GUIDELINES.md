# OWNEX Brand Guidelines

## Brand Identity

OWNEX is an **Autonomous Work Operating System**—not a tool, not a dashboard, not a collection of scripts. The brand must communicate:

- **Intelligence** — Autonomous decision-making
- **Autonomy** — Self-directed operation
- **Precision** — Accurate, calculated action
- **Opportunity** — Discovering and preparing work
- **Orchestration** — Coordinating tools, agents, models
- **Engineering** — Technical excellence
- **Control** — Human at the decision gate
- **Clarity** — Transparent operation
- **Future** — Forward-looking technology

---

## Brand Voice

### Tone

**Professional, Technical, Precise**

OWNEX speaks like an engineering team at a serious technology company. Not like a startup, not like a crypto project, not like an AI toy.

### Voice Characteristics

- **Direct**: Say what you mean. No fluff.
- **Technical**: Use precise terminology. Not "smart" when you mean "autonomous".
- **Honest**: Don't overpromise. The system does what it does.
- **Confident**: Own the product's capabilities without hype.
- **Serious**: This is engineering, not entertainment.

### Copy Guidelines

**Do**:
- "Autonomous work operating system"
- "Intelligent opportunity discovery"
- "Multi-provider AI runtime"
- "Zero-barrier opportunity spectrum"
- "System health monitoring"

**Don't**:
- "AI-powered super brain"
- "Game-changing revolutionary tech"
- "Unleash the power of AI"
- "Transform your life forever"
- "Work while you sleep" (unless literally true)

## Logo Usage

### Primary Lockup

**When to use**:
- Repository header (README.md)
- Documentation main pages
- Website hero
- Marketing materials (primary placement)

**When NOT to use**:
- Favicon (use mark only)
- App icons (use mark only)
- Very small sizes (< 100px width)

**Minimum size**: 200px width
**Clearance**: 24px on all sides

### Mark (Symbol Only)

**When to use**:
- Favicon
- App icons
- Small UI elements (< 100px)
- When wordmark is too large for context

**When NOT to use**:
- Primary branding (use lockup)
- When full identity is needed

**Minimum size**: 32×32px
**Clearance**: 8px on all sides

### Color Variants

| Variant | Background | Use Case |
|---------|------------|----------|
| `ownex-lockup.svg` (blue) | Light | Standard use on light backgrounds |
| `ownex-lockup-white.svg` | Dark | Use on dark backgrounds (#0B0B0B, #1A1A1A) |
| `ownex-lockup-black.svg` | Light | Alternative for light backgrounds |

**Rule**: Always ensure sufficient contrast. White on light gray is prohibited.

### Logo Misuse

**Do NOT**:
- Stretch or distort the logo
- Change the logo colors
- Add effects (shadows, glows, gradients) to the logo
- Use the logo as a background pattern
- Rotate the logo (except 90° increments for specific use cases)
- Add text around the logo to create a new lockup
- Use the logo in a sentence

## Color Usage

### Primary Colors

**Ownex Blue (#2D7FF9)**:
- Primary accent color
- Use for: links, buttons, badges, active states, highlights
- Never use as background for large areas

**Black (#0B0B0B)**:
- Primary background color
- Use for: main backgrounds, dark surfaces
- Not for: text on dark backgrounds

**White (#FFFFFF)**:
- Primary surface color
- Use for: light backgrounds, text on dark
- Not for: text on light backgrounds

### Accent Colors

**Gold Accent (#D4AF37)**:
- Premium touches only
- Maximum 2 instances per hero/layout
- Use for: subtle highlights, borders, decorative elements
- Never for: primary CTAs, links, status indicators

### Color Rules

1. **No rainbow colors** — Strict adherence to the defined palette
2. **No neon cyberpunk** — Colors are muted, professional
3. **Gradients only** — Ownex Blue → Ownex Deep Blue
4. **Contrast required** — WCAG AA minimum (4.5:1)
5. **No arbitrary colors** — Every color must be from the palette

## Typography

### Font Stack

**Primary**: Inter, -apple-system, BlinkMacSystemFont, 'Segoe UI', Roboto, sans-serif
**Code**: 'Fira Code', 'JetBrains Mono', 'SF Mono', Consolas, monospace

### Usage Rules

- **Display (72px)**: Hero titles only
- **Heading (48px)**: Section headings
- **Subheading (36px)**: Subsection headings
- **Body (24px)**: Main content
- **Secondary (18px)**: Supporting text
- **Caption (14px)**: Metadata, labels
- **Small (12px)**: Legal, disclaimers

### Typography Misuse

**Do NOT**:
- Use display sizes for body text
- Mix random weights (stick to 400, 600, 700)
- Use excessive letter-spacing (keep to -2, 0, +2)
- Use display fonts for code
- Use all caps for body text

---

## Spacing

### Spacing Scale

Use the 8px grid: 4, 8, 12, 16, 24, 32, 48, 64

**Rules**:
- Everything is a multiple of 4px
- Minimum 16px between elements
- Minimum 48px between major sections
- Generous whitespace is encouraged

---

## Imagery

### Hero Artwork

**Purpose**: Establish brand identity, create visual interest
**Frequency**: 1 per repository
**Style**: Abstract, geometric, technical
**No**: Stock photos, generic AI art, literal screenshots

### Product Screenshots

**Purpose**: Show real software functionality
**Frequency**: 5-8 unique screens
**Style**: Real application, representative state
**No**: Fake UI, generated dashboards, promotional renders

### Supporting Illustrations

**Purpose**: Clarify concepts, explain architecture
**Frequency**: Minimal
**Style**: Clean diagrams, technical drawings
**No**: Decorative flourishes, clip art, stock illustrations

---

## Visual Hierarchy

### Information Architecture

```
Level 1: Brand Identity (Logo, Hero)
Level 2: Product Evidence (Screenshots)
Level 3: Technical Information (Architecture, Docs)
Level 4: Supporting Details (Examples, Guides)
Level 5: Meta Information (Badges, Links)
```

**Rule**: Level 1 must not compete with Level 2. The product is the star.

## Dos and Don'ts

### Do

- Use the primary lockup for branding
- Ensure sufficient contrast
- Follow the spacing system
- Show real software in screenshots
- Use technical, precise language
- Maintain generous whitespace
- Keep layouts clean and uncluttered
- Use SVG for logos and icons
- Optimize image file sizes
- Validate all links and assets

### Don't

- Stretch or distort the logo
- Use arbitrary colors
- Add unnecessary effects
- Overuse the gold accent
- Create fake UI screenshots
- Use hype language
- Clutter layouts with too many images
- Use stock photos
- Leave broken links
- Ignore the design system

## Quality Standards

### Visual Quality Checklist

Before publishing any visual asset:

- [ ] No pixelation at any size
- [ ] No cropping errors
- [ ] No broken transparency
- [ ] No unexpected borders
- [ ] No color mismatches
- [ ] No compression artifacts
- [ ] No accidental text
- [ ] No misaligned elements
- [ ] File size is optimized
- [ ] Format is appropriate (SVG vs PNG)

### Professional Standards

Reject designs that look like:
- Generic startup template
- Canva template
- AI-generated slop
- Stock illustration
- Generic cyberpunk
- Overloaded gradient
- Random neon
- Excessive glassmorphism
- Fake 3D
- Generic "AI brain"
- Generic robot
- Generic circuit
- Random glowing orb

## Asset Management

### Asset Registration

Every asset must be registered in `ASSET_REGISTRY.md` before use.

### Asset Naming

Use deterministic names:
- `ownex-hero-primary.svg` ✅
- `mission-control.png` ✅
- `social-preview.png` ✅

Not:
- `final.png` ❌
- `new-banner.svg` ❌
- `screenshot1.png` ❌

### Versioning

Do not create versioned files:
- `hero-final-v2.png` ❌
- `logo-new.svg` ❌

Instead:
- Replace the canonical asset
- Update the registry
- Document the change

## Platform-Specific Guidelines

### GitHub

- README must render correctly in dark and light mode
- Use system fonts (no external font loading)
- Limit to 8 screenshots total
- Ensure mobile readability (390px width)
- Use relative paths for images

### Website

- Can use custom fonts
- Can use larger imagery
- Must follow the same design system
- Must be responsive

### Documentation

- Can use more screenshots
- Can use diagrams
- Must follow the design system
- Must be accessible

## Review Process

### Before Publishing

1. Check asset registry for compliance
2. Validate all links and references
3. Test in dark and light mode
4. Test on mobile (390px width)
5. Run validation script
6. Get visual review

### Approval Criteria

- [ ] Asset is registered
- [ ] Asset follows design system
- [ ] Asset serves a clear purpose
- [ ] Asset is necessary (not decorative clutter)
- [ ] Asset is high quality
- [ ] Asset is referenced correctly

---

## Brand Evolution

### When to Update

The brand should evolve when:
- The product strategy changes significantly
- The visual identity no longer fits the product
- Quality standards improve
- Platform requirements change

### Process

1. Update DESIGN_SYSTEM.md
2. Update BRAND_GUIDELINES.md
3. Update ASSET_REGISTRY.md
4. Create new assets
5. Migrate references
6. Validate everything
7. Communicate changes

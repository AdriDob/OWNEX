# OWNEX — TYPOGRAPHIC IDENTITY SYSTEM

Redesign and establish the complete typographic identity of OWNEX.

OWNEX is an Autonomous Work Operating System designed around intelligence, autonomy, precision, opportunity discovery, orchestration and advanced software engineering.

The typography must feel like a serious technology product that could become a globally recognized software company.

---

## PRIMARY TYPEFACE

Use:

# Sora

Sora must become the primary OWNEX brand typeface.

Use the appropriate weights:

* Regular
* Medium
* SemiBold
* Bold

Do not use excessive font weights.

Prioritize:

clarity

geometry

precision

premium appearance

technical character

excellent readability

## WORDMARK

Do NOT simply type:

OWNEX

in Sora and consider the work finished.

Use Sora as the starting point for a CUSTOM OWNEX WORDMARK.

The final wordmark should preserve the readability of:

OWNEX

but introduce subtle custom geometry.

Investigate carefully modifying:

* O
* X
* letter spacing
* terminal geometry
* optical spacing
* relationship between O and X

The modifications must be subtle.

Do not make the wordmark difficult to read.

Do not turn it into an experimental font.

The objective is:

recognizable typography + proprietary character.

---

## O / X RELATIONSHIP

The letters:

O

and

X

should have a subtle visual relationship with the OWNEX symbol.

Explore whether the geometry of:

O

can visually suggest:

a node

a portal

a nucleus

a route

a convergence

while:

X

can suggest:

intersection

decision

direction

convergence

Do NOT use literal arrows or generic AI symbols.

The connection should be abstract and sophisticated.

---

## LETTER SPACING

Use generous but controlled spacing.

The word:

OWNEX

must feel engineered.

Avoid:

compressed startup typography

excessively wide tracking

decorative spacing

random kerning

The final wordmark should remain strong at small sizes.

## GITHUB

Optimize typography for GitHub.

Remember that GitHub does not guarantee custom web fonts inside Markdown.

Therefore:

* brand assets should be rendered into SVG where appropriate
* README text must remain compatible with GitHub's native rendering
* do not depend on external CSS for the core README
* do not create unreadable typography for the sake of branding

## IMPORTANT

Do not over-design.

The goal is NOT to make OWNEX look futuristic by adding visual tricks.

The goal is to make OWNEX look technologically advanced through:

typography

geometry

spacing

proportion

precision

restraint

The identity should feel inevitable, as though OWNEX could not have been designed any other way.

Use Sora as the foundation.

Use Geist as the software/documentation voice.

Use JetBrains Mono as the technical voice.

Create a subtle proprietary OWNEX wordmark rather than simply typing the company name in a font.

After implementation, visually inspect every generated asset and fix inconsistencies.

Do not leave duplicate, broken or low-quality typography assets.

The final result must look like a professional global technology brand.
